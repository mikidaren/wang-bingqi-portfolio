### 部署踩坑：资源上传通道抖动（重要）

`wrangler deploy` 在 `POST /accounts/{id}/workers/scripts/<name>/assets-upload-session` 阶段报 `fetch failed` 中断，本次**连续失败 4 次、第 5 次才成功**。

- **根因**：国内到 Cloudflare 上传通道的**间歇性抖动**，非配置问题。同期用 Node `fetch` 直测同一端点是 2 秒 HTTP 200，wrangler 侧却 22 秒超时断开。
- **环境特征**：`api.cloudflare.com` 被代理软件解析到 **fake-IP `198.18.0.160`**（Clash 一类 TUN 模式）；curl 走系统代理稳定，Node 通道偶发不稳。DNS 无 IPv6。
- **重要性质**：wrangler 的资源上传**按内容哈希去重**。首次已传 35/53，后续重跑输出 `Uploaded 18 of 18 assets (35 already uploaded)` —— **重跑只传缺失部分，不会白费**。
- **对策**：不要改配置，**直接重跑 `npm run deploy`**（建议循环重试）。可设 `WRANGLER_SEND_METRICS=false` 减少无关遥测请求（它自己也在报 fetch failed，干扰判断）。
